已有队列、转换关联、幂等和状态展示已由同容器执行器复用。旧 Windows 工作进程入口仅为兼容保留，服务端不要求配对外部电脑。Docker 源码接入及本地 WSL 镜像构建、容器启动已完成；真实授权导入、歌曲上传和用户播放验证均已完成。

## 三个验证门槛

### 1. Linux 算法执行

先在 Linux/amd64 环境验证 SAP 初始化、握手和音频签名，再进行实际容器验收；其他架构另行验证。将宿主 Windows API 依赖逐项变成可检验的兼容实现，保留原来的范围校验和错误边界。

用户已确认目标为 Intel/AMD x86_64，ARM 可选，不阻塞本轮。REA/Ghidra 已可用，最新观测见 [上传内核调查记录](rea-linux-upload-investigation.md)。

字符编码、区域映射和分类需要与实际调用的 Windows 语义一致，不能直接用近似 `casefold`、固定成功返回值或跳过检查替代。未知调用明确停止。Apple 程序文件不提交或打入公开镜像。

通过条件：目标算法实际在 Linux 运行；每个替换 API 有离线对照；签名链路真实验证通过。仅能导入 Python 模块或启动容器不算通过。

### 2. 桌面授权导出与服务端安全导入

优先复用已验证的 Windows 授权入口，导出上传所需的完整账号及资料库上下文；若 macOS 路线更合适，再研究对应授权和算法实现。当前没有 macOS 授权工具，不能仅凭用户已登录 macOS 就宣称可直接导出。

DPAPI 仅用于 Windows 本机保护，不能直接作为容器授权文件。需要在授权机器本地解密后重封装为可移植的加密授权包，再由服务端安全导入；不得通过聊天、日志、普通响应或仓库传输明文凭据。容器内凭据加密保存，密钥单独管理，账号/资料库切换时拒绝恢复旧任务。

通过条件：桌面授权导入后，关闭授权电脑，容器仍可独立上传和重启恢复；授权被拒绝时暂停，不重复新增歌曲；重新导入同账号授权后按原记录安全恢复。无需先证明网页令牌能替代桌面授权。

### 3. 独立上传闭环

前两项通过后，使用用户明确指定的歌曲进行真实上传。保留原始记录并避免重复新增；未知请求结果停止重发。补齐指纹分支前明确实验范围。

通过条件：容器中完成所需单曲协议和资产，另一设备验证播放、标签、封面和歌词；容器重启后可安全恢复；不需要启动 Windows 电脑。
